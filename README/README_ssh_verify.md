# Linux Hardening — SSH Verify Module

Ansible-плейбук для автоматической проверки того, что модуль `ssh_hardening` реально применился и работает — не просто "playbook прошёл без ошибок", а что hardening подтверждён по факту: конфигом sshd, правами на файлы и живой попыткой подключения.

## Что делает playbook

Роль `ssh_verify` прогоняет три блока проверок на каждом хосте:

**1. Эффективная конфигурация sshd**
Через `sshd -T` (а не `grep` по файлу конфига) проверяется то, что демон реально применил, с учётом дефолтов:
- `PermitRootLogin no`
- `PasswordAuthentication no`
- `PubkeyAuthentication yes`

**2. Файлы и права на хосте**
- `~/.ssh` существует и имеет права `0700`
- Публичный ключ проекта присутствует в `authorized_keys`

**3. Реальные попытки подключения — с control-ноды**
- Вход под `root` — должен быть **отклонён**
- Вход по паролю — должен быть **отклонён**
- Вход по ключу — должен **пройти**

Если любая проверка проваливается — playbook сразу останавливается на этом task с чётким `FAIL:`-сообщением, а не копит ошибки молча до конца прогона.

## Структура

roles/
└── ssh_verify/
├── defaults/
│ └── main.yml # пути к ключевой паре, используемым для проверки
└── tasks/
└── main.yml # вся логика проверок
playbooks/
└── verify_ssh_hardening.yml # точка входа

Роль переиспользует ту же ключевую пару, что была сгенерирована `ssh_keygen` и раскатана `ssh_hardening` — отдельно ничего не генерирует и не хранит.

## Зависимости

**`sshpass` на control-ноде** — обязателен. 
```bash
sudo apt install sshpass
```

Переменные подключения (`ansible_password`, `ansible_user`, etc.) берутся из тех же `inventory/group_vars/linux_hosts/vars.yml` и `vault.yml`, что и в модуле hardening — ничего дополнительно настраивать не нужно, если `ssh_hardening` уже отработал.

## Запуск

```bash
ansible-playbook playbooks/verify_ssh_hardening.yml
```

Запускать можно сколько угодно раз — playbook только читает состояние хостов и пытается подключиться, ничего не меняет (`changed=0` во всех задачках всегда, кроме случаев реальной поломки).
