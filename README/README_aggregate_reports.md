# Linux Hardening — Aggregate Reports

Собирает все текстовые отчёты, сгенерированные `*_verify`-ролями по каждому хосту, в один сводный файл — чтобы не открывать по очереди 8-10 отдельных файлов, а посмотреть всё разом.

## Что делает

Находит все `*.txt`-файлы в `reports/<host>/` (кроме самого сводного файла из прошлого прогона), сортирует по имени, читает содержимое каждого и склеивает в один файл `_full_report.txt` с заголовками-разделителями между секциями.

Работает полностью локально на control-ноде (`delegate_to: localhost` во всех тасках) — реального SSH-подключения к test1/test2 не требует, `become` не нужен.

## Структура

```
roles/aggregate_reports/
├── defaults/main.yml
├── tasks/main.yml
└── templates/
└── full_report.j2
```

## Запуск

Логичный порядок — сначала прогнать все проверки, потом собрать сводку:

```bash
ansible-playbook playbooks/verify_all.yml
ansible-playbook playbooks/aggregate_reports.yml
cat reports/test1/_full_report.txt
```

`aggregate_reports.yml` уже включён в конец `verify_all.yml` — при обычном запуске `verify_all.yml` (или `all.yml`) сводный отчёт собирается автоматически, отдельно вызывать не обязательно.

## Результат

```
reports/test1/_full_report.txt
```

Содержит по порядку (алфавитно) все отчёты, которые на данный момент существуют для этого хоста — сколько модулей verify прогонялось, столько секций и попадёт в сводку. Если какой-то `*_verify`-плейбук ещё не запускался — соответствующей секции просто не будет, без ошибок.

## Важный нюанс

Файл `_full_report.txt` исключён из поиска исходников (`excludes` в `find`), чтобы при повторных запусках не включать сам себя и не расти бесконтрольно с каждым прогоном.

Если добавляешь новый `*_verify`-модуль в проект — отдельно ничего делать не нужно: как только он один раз отработает и создаст свой `.txt` в `reports/<host>/`, при следующем прогоне `aggregate_reports.yml` он автоматически попадёт в сводку.
